# Фикстуры (стресс-набор входов)

Каждая фикстура провоцирует свой класс риска. Тесты должны гоняться по всем.

| Файл | Что проверяет |
|---|---|
| `manometer_basic.json` | «правильный» сценарий из ТЗ (мансметр DM 02) |
| `trm1_catalog_slice.json` | многовариантность + реальные данные каталога (кусок таблицы 2ТРМ1, 3 варианта) |
| `manometer_latin_keys.json` | ключи латиницей (`range`, `precision`) — нормализация синонимов |
| `thermometer_specs_string.json` | specs строкой вместо dict — устойчивость парсинга |
| `flowmeter_empty_blocks.json` | пустые блоки (specs = {}, description = "") |
| `levelmeter_contradiction.json` | противоречие specs vs паспорт (0–20 м против 0–10 м) |
| `pressure_controller_code_only.json` | минимальный вход — только код товара в названии |

## Проверяемые инварианты тестами

1. Система не падает ни на одной фикстуре (graceful degradation).
2. Ни один факт из входа не потерян: ключи specs ⊆ вывода (полнота).
3. «данных нет» там, где поля пустые/отсутствуют — без выдумки.
4. Противоречия (specs vs description) флагуются в `warnings`, а не тихо «исправляются».
5. Торговые поля (цена/наличие/срок поставки) не попадают в характеристики.
6. Вербатим: коды модификаций (2ТРМ1-Щ2.У2.И.РС, код товара) переходят в вывод без изменений.

> Тесты гоняются без сети и ключа: в `tests/` LLM заменён test double (`FakeLLMProvider`). В продакшене (`app/`) имитаций нет — только реальный API.
